# 会话操作菜单与管理设计规格

## 目标

为工作区左侧会话列表增加会话行操作菜单，支持重命名和确认后永久删除；同时在新会话标题输入区域与会话列表之间增加轻微间距。新增 UI 必须复用当前项目的纸张手绘视觉语言，不引入黑色浮层、紫色主题或新的图标依赖。

## 现有上下文

- 页面入口：`frontend/src/views/WorkspaceView.vue`
- 会话状态：`frontend/src/stores/workspace.store.ts`
- 会话 HTTP 服务：`frontend/src/services/chat.service.ts`
- 后端路由：`backend/app/api/routes.py`
- 后端会话服务：`backend/app/services/chat_service.py`
- 数据库：SQLite 中的 `chat_sessions`、`chat_messages`，以及通过 `tasks.chat_session_id` 建立的任务关联
- 现有字体：`Architects Daughter`，辅助使用 `JetBrains Mono`
- 现有视觉基线：`#f5f0e8` 纸张背景、`#2a2a2a` 铅笔色、`#d8d0c4` 浅边框、`#d4a017` 黄色强调、`#b83030` 红色危险色
- 当前项目没有通用 Modal/Dialog 组件或图标库，图标使用内联 SVG、Unicode 字符和少量 Emoji

## 用户体验

### 会话列表

1. 新会话标题输入框和新建按钮保持现有横向布局。
2. 表单与会话列表之间增加一个紧凑间距，并保留清晰分隔。
3. 每个会话行右侧增加三点操作按钮。
4. 三点按钮使用项目现有内联图标风格，使用 `currentColor`，默认低干扰；悬停、键盘聚焦或菜单打开时提供明显反馈。
5. 会话标题继续单行省略，更新时间继续作为次要信息显示。
6. 当前会话继续保持现有 active 状态，只增强操作按钮和菜单状态，不改变会话打开行为。

### 操作菜单

- 点击三点按钮打开当前会话的下拉菜单，再次点击关闭。
- 同一时间最多有一个菜单打开；切换到另一行时关闭之前的菜单。
- 点击菜单外部、按 `Escape` 或切换面板时关闭菜单。
- 菜单使用项目纸张背景、铅笔色边框、现有浅边框阴影和现有字体。
- 菜单项包含：
  - 编辑图标 + “重命名”
  - 删除图标 + “删除会话”，使用项目红墨色
- 不增加黑色面板、渐变、玻璃效果或第三方图标包。

### 重命名

1. 点击“重命名”后关闭菜单，并显示独立项目风格弹窗，标题为“重命名会话”。
2. 输入框预填当前标题并自动获得焦点，使用项目现有纸张输入框样式；弹窗使用 `role="dialog"`、`aria-modal="true"` 和 `aria-labelledby`。
3. 点击“确认”或按 `Enter` 提交重命名；`Escape`、点击遮罩或点击“取消”关闭弹窗且不保存。全局 `Escape` 优先取消重命名弹窗，不触发其他编辑逻辑。
4. 空白标题不提交，保留弹窗和草稿，避免产生空标题请求。
5. 提交期间输入框和取消、确认按钮均 disabled，确认按钮显示“保存中…”。
6. 成功后同步更新列表和当前会话标题并关闭弹窗；请求失败时保留弹窗与输入内容，继续使用 `store.error` 的既有错误提示。
7. 不保留行内编辑实现；重命名菜单按钮继续使用 `data-testid="session-rename"`，弹窗表单、输入框、取消和确认按钮分别提供稳定测试标识。

### 删除确认

1. 点击“删除会话”后关闭下拉菜单并显示项目风格确认对话框。
2. 对话框明确显示会话标题，并说明将永久删除该会话及全部消息且无法恢复。
3. “取消”关闭对话框，不产生数据变更。
4. “删除会话”执行永久删除；确认按钮使用红墨色边框和文字，不使用黑色危险面板。
5. 对话框支持键盘操作，默认焦点放在“取消”或安全操作上；`Escape` 等同取消。
6. 删除执行期间禁用两个对话框按钮，防止重复提交。
7. 删除失败时关闭进行中状态并显示可理解的错误，不从列表中移除未成功删除的会话。

### 删除后的导航

- 删除当前会话前关闭该会话的 SSE 连接。
- 若仍有其他会话，打开删除后列表中的第一条会话并加载其消息。
- 若没有其他会话，清空当前会话 ID 和消息区，回到工作区无会话状态。
- 删除非当前会话只从列表中移除对应行，不改变当前聊天内容。
- 删除会话及其消息；将关联任务的 `chat_session_id` 清空以解除关联，但保留任务记录、工作区文件及其他工作区数据。

## API 与数据行为

### 重命名

新增会话标题更新接口，推荐使用：

```text
PATCH /api/v1/chat-sessions/{sessionId}
```

请求体只允许：

```json
{ "title": "新的会话标题" }
```

服务端要求：

- 校验会话存在及可访问的工作区归属。
- 对标题执行 `strip()`。
- 空标题返回校验错误，不回退为“新会话”。
- 成功后更新 `title` 与 `updated_at`，返回完整 `ChatSession`。
- 请求模型继续禁止未声明字段。

### 永久删除

新增：

```text
DELETE /api/v1/chat-sessions/{sessionId}?workspaceId={workspaceId}
```

服务端要求：

- 校验会话存在及工作区归属，不允许跨工作区删除。
- 使用事务删除该会话关联的消息，先将关联任务的 `chat_session_id` 清空，再删除会话记录。
- 只删除会话相关数据，不触碰工作区注册信息、文件或 Provider 配置。
- 删除成功返回无内容成功响应或项目已有的统一成功响应约定。
- 删除失败保持事务一致性，不产生部分删除。

## 前端分层

- `chat.service.ts` 增加重命名和删除请求方法，并沿用现有 HTTP 错误处理与 DTO 校验方式。
- `workspace.store.ts` 增加重命名、删除和删除后导航所需 action；复用现有会话切换、消息清空、SSE 清理和列表更新逻辑。
- `WorkspaceView.vue` 增加菜单开关、编辑标题、确认对话框和键盘交互；样式继续放在该单文件组件的 scoped style 中，沿用当前硬编码视觉值，不在本任务中做无关的全局 token 重构。
- 图标使用内联 SVG 或现有 Unicode 方案，不引入依赖。

## 错误处理与安全

- 用户界面不显示原始异常、Provider URL、密钥或内部路径。
- 后端删除和更新始终校验会话与工作区关联。
- 前端请求失败时不乐观删除，不丢失原会话标题。
- 对删除按钮执行中状态做幂等保护。
- 不将标题内容拼接到 HTML；使用 Vue 的文本绑定。

## 测试要求

### 前端

- service 测试：重命名 PATCH 请求体严格只含 `title`；删除 DELETE 请求包含正确会话和工作区；异常响应按现有契约处理。
- store 测试：重命名成功同步列表；删除当前会话关闭 SSE 并切换到下一会话；删除最后一个会话清空状态；删除非当前会话不影响当前消息；失败时保留原状态。
- WorkspaceView 测试：三点菜单开关、菜单外部/Escape 关闭、重命名 Enter/Escape/空白标题、确认框取消/确认、删除期间按钮禁用和正确 data-testid。

### 后端

- service 测试：标题更新成功、空标题拒绝、更新工作区归属校验。
- service 测试：删除会话清理消息并解除任务关联、工作区归属校验、事务失败不部分删除。
- API/schema 测试：禁止未知字段，错误响应不泄露敏感信息。

## 非目标

- 不增加会话收藏、置顶、归档、恢复、批量删除或拖拽排序。
- 不删除工作区磁盘文件。
- 不重做整个 WorkspaceView 的视觉系统。
- 不引入独立设计系统、第三方图标库或通用弹窗框架。

## 验收标准

- 新建区域与会话列表之间有可见但紧凑的间距。
- 每个会话行右侧可通过键盘访问三点按钮并打开菜单。
- 菜单和确认框与项目纸张手绘风格一致，颜色、字体、边框和阴影不出现黑色主题偏差。
- 重命名可成功保存、取消和处理空白输入。
- 删除必须经过确认，确认后永久删除会话及其消息关联数据。
- 当前会话、非当前会话和最后一个会话的删除后导航正确。
- 前后端相关测试、前端 typecheck、lint 和 build 通过。
