# 多供应商设置页设计

## 目标

将 `/settings` 重构为符合 LightCode 暖纸视觉语言的多供应商配置中心：保留原项目已有的主侧边栏，设置分类暂时只保留“模型与供应商”和“关于”，并在“模型与供应商”分类中提供供应商列表、搜索、右侧配置摘要以及“添加供应商”弹层。

本阶段先完成经过浏览器确认的视觉与交互结构；正式实现需要同步扩展前端视图、服务合约、后端多供应商配置模型和安全凭据存储边界。

## 已确认的用户流程

1. 用户从原项目已有的设置入口进入 `/settings`。
2. 设置页沿用原项目的主侧边栏和 SVG 图标风格，不重新设计工作区、文件浏览、会话、设置入口。
3. 设置页分类只显示“模型与供应商”和“关于”。
4. 默认进入“模型与供应商”，中间区域展示供应商搜索框和供应商列表。
5. 选择供应商后，右侧展示该供应商的配置安全摘要。
6. 点击“添加供应商”后，显示暖纸色弹层。
7. 在弹层中选择供应商模板，填写配置名称、模型 ID、API Key、Base URL，并设置启用状态。
8. “测试连接”展示连接测试反馈；“测试并添加”关闭弹层并作为未来正式保存动作的入口。

## 页面结构

### 主侧边栏

直接复用 `frontend/src/views/WorkspaceView.vue` 中已有的侧边栏结构和 SVG 图标路径。正式实现不复制 HTML 原型中的简化字符图标，也不新增第二套主导航视觉。

### 设置分类栏

设置分类栏使用当前项目暖纸视觉，仅包含：

- 模型与供应商：默认选中。
- 关于：暂时只作为分类入口，内容可在后续单独实现。

暂不加入偏好设置、默认模型、快捷键、本地数据等分类。

### 供应商列表栏

- 标题“供应商”和配置数量。
- 搜索输入框，可按供应商名称或模型 ID过滤。
- 供应商列表项包含供应商缩写图标、名称、模型 ID和状态点。
- 当前选中项使用浅黄色纸张高亮与铅笔色边框。
- 无匹配结果时显示暖色空状态。
- 底部固定“＋ 添加供应商”主操作。

### 右侧详情区

当前已确认的 section 视觉和结构保持不变：

- 未选择时显示选择提示和安全说明。
- 选择供应商后显示供应商缩写、名称、模型 ID和状态徽章。
- 下方展示运行期配置、模型权限、安全视图三块摘要。
- 不显示 API Key、完整 Base URL、Authorization header或上游原始响应。

## 添加供应商弹层

弹层使用暖白纸张背景、细铅笔边框、轻微纸张纹理和暖灰半透明遮罩，不使用截图中的黑色背景。

内容顺序：

1. 标题“添加供应商”和说明文字。
2. 供应商协议模板按钮网格：OpenAI、OpenAI Compatible、DeepSeek、Qwen、Kimi、OpenRouter、SiliconFlow、Ollama。
3. 配置名称和模型 ID。
4. API Key 密码输入框，以及不持久化提示。
5. Base URL输入框。
6. 启用此供应商开关与测试前置说明。
7. “测试连接”和“＋ 测试并添加”操作。
8. 凭据安全边界说明。

## 视觉方向

- 背景：使用现有 `#f5f0e8` 暖纸色和轻微暖色/蓝灰色环境纹理。
- 文字：延续 Architects Daughter、Caveat、Patrick Hand和JetBrains Mono的现有分工。
- 边框：使用浅灰棕色细边框、虚线分隔和轻微不规则圆角。
- 强调：黄色表示当前选择和主要保存动作；蓝色表示测试连接；绿色表示就绪；红色只表示错误或危险操作。
- 信息层次由间距、字体和边框承担，不添加黑色大面积面板、强烈发光或无必要的装饰性渐变。
- 弹层在桌面宽度下保持单个居中表单，在窄屏下允许内容滚动。

## 数据与安全边界

当前后端只支持一份运行期 Provider 配置，因此正式实现多供应商时需要独立的设计与实现工作：

- Provider 配置应具有稳定标识、展示名称、协议类型、模型 ID、Base URL摘要和启用状态。
- API Key只能由本机后端设置端点接收，前端仅在提交瞬间持有输入值。
- 凭据应通过可替换的 `ProviderCredentialStore` 管理；开发期内存实现不落盘，Electron阶段替换为系统密钥库。
- SQLite、前端持久化状态、日志、SSE、错误响应和安全摘要不得包含 API Key、Authorization header、完整 Base URL或原始上游响应。
- 测试连接必须沿用现有 HTTPS origin allowlist、显式超时、`trust_env=False`和`follow_redirects=False`约束。
- 多供应商列表可以展示安全摘要，但不能将视觉预览中的完整配置字段误当作安全响应字段。

## 正式实现边界

本设计不包含：

- 偏好设置、默认模型、快捷键、本地数据分类的具体内容。
- 多供应商后端 schema、迁移、CRUD API和凭据存储的具体实现。
- 多供应商默认模型选择策略。
- Electron系统密钥库接入。
- 真实供应商连接测试在当前预览中的执行。

正式实现应先为多供应商服务合约和安全凭据模型补充测试，再修改 `SettingsView.vue`，最后运行前端全量测试、类型检查和构建；后端变更还需运行后端全量测试。
